# skill_issue: подготовка к вёрстке

## Основное направление

Тёмная мастерская разработчиков: моноширинная типографика, простой поиск команды
по навыкам, горизонтальная навигация и списки с тонкими разделителями.
Синий акцент по умолчанию. Без градиентов, теней, свечения, аватаров, иллюстраций,
декоративных бейджей и плиток с иконками. Не превращать главную в dashboard.

Название продукта — `skill_issue`. Логотип — `❯ skill.issue`: шеврон и точка
используют акцентный цвет, буквы — основной цвет текста. На сайте логотип
набирается настоящим JetBrainsMono Nerd Font Mono 600; PNG-концепт служит
визуальным ориентиром. Шеврон — декоративный SVG с пропорцией 2:3 без сжатия
во flex-контейнере; доступное имя логотипа — `skill.issue`.

Интерфейс, сообщения и ошибки — на английском; язык HTML — `en`.
Описание главной — `Find your dream team without issues.`, слоган в её футере —
`No team? Skill issue.`. На входе — `Good to see you at`
и уменьшенный текстовый логотип без шеврона. Favicon — синий SVG-шеврон
`static/favicon.svg`, общий для обычных страниц и страниц ошибок.
Ошибки полей — `This field is required.` или `Enter a valid value.`;
ограничения вроде длины пароля и запрета пробелов остаются в подсказке.
Русские надписи в старых макетах и описаниях ниже передают смысл, но не финальный текст.

Макеты созданы встроенным imagegen для обсуждения. Они задают композицию,
но не являются точной спецификацией шрифта, цветов, размеров и возможностей сервера.
Переливы на изображениях не переносить в CSS. При расхождении приоритет имеют
этот документ, реальные модели проекта и настоящий загруженный шрифт.

- [Скрин сообщества](references/developer-community.png), предоставленный автором.

использовать текстовые действия и только необходимые служебные значки в стиле референса.

## Шрифт и подключение

Локальные файлы: `static/fonts/jetbrains-mono/`. Семейство:
`JetBrainsMono Nerd Font Mono`. Начертания: 400 для основного текста,
500 для навигации, 600 для заголовков и основных действий. Не подменять на
пропорциональный Nerd Font Propo и не использовать искусственный bold 700.
Кириллица и Nerd Font glyphs сохранены. Файлы WOFF2 подготовлены из официальных TTF;
происхождение, версия и лицензия находятся рядом со шрифтами.

При вёрстке подключить после Bootstrap и до стилей страниц:

```html
<link rel="stylesheet" href="/static/css/fonts.css">
<link rel="stylesheet" href="/static/css/design-tokens.css">
<link rel="stylesheet" href="/static/css/site.css">
```

Эти файлы подключены к главной, входу и регистрации. `fonts.css` объявляет
шрифты, `design-tokens.css` содержит только переменные. В `site.css` находятся
общая тема, типографика, шапка, кнопки и сообщения. После него главная подключает
`home.css`, а вход и регистрация — `auth.css` с формами и их композицией.
Базовая типографика:

```css
body {
    color-scheme: dark;
    font-family: var(--bs-body-font-family);
    font-size: var(--bs-body-font-size);
    font-size-adjust: 0.55;
    line-height: var(--bs-body-line-height);
    color: var(--dm-text);
    background-color: var(--dm-background);
}

button,
input,
select,
textarea {
    font: inherit;
}
```

`font-size-adjust` соответствует x-height загруженного шрифта; в старых браузерах
остаётся моноширинный fallback. Не добавлять preload всех начертаний;
первым использовать 400, остальные загружать по мере использования.
Статический middleware уже поддерживает `font/woff2`, а `.csproj` копирует `static/`
в сборку и публикацию. Не нужны CDN, npm-пакеты или изменения сервера для шрифтов.

## Цвет, размеры и адаптивность

Источник значений — `static/css/design-tokens.css`. Фон `#101010`, поверхность
`#191919`, текст `#ededed`, вторичный текст `#aaaaaa`, акцент `#58a6ff`.
На акцентной кнопке — тёмный текст. Цвет `#303030` используется для декоративных
разделителей; для различимых границ полей — `#767676`.

Шрифт переопределяется через `--bs-body-font-family`; размер текста, межстрочный
интервал и скругления используют стандартные переменные Bootstrap. Общих CSS-переменных
для шкалы отступов в Bootstrap нет: в CSS используются значения в rem, в HTML —
существующие utility-классы Bootstrap. Неиспользуемые токены размеров удалены.

Основной текст — 1rem с межстрочным интервалом 1.5, вторичный — 0.875rem,
заголовки секций — 1.5rem. Ширина контента — до 65rem, админки — до 74rem,
форм авторизации — до 30rem. Скругление — 0.375rem. Отступы кратны 0.25rem.

На узких экранах боковые отступы от 1rem, блок заявки команды переносится под
описание. Навигация переносится без обрезки имени. Текст и длинные ссылки
переносятся; таблица админки может иметь собственную горизонтальную прокрутку.
Проверить ширину 320 CSS px и увеличение текста до 200%. Для кнопок и полей
сохранить существующую минимальную высоту 3rem, не фиксировать высоту текста.

Акцент применяется через `data-accent` на `<html>`: отсутствие атрибута или
`blue` — синий, `green`, `purple`, `amber` — другие варианты.
CSS-переменные готовы; сохранение выбора пользователя ещё не реализовано.
Это личная настройка всего сайта, не цвет публичного профиля.

## Страницы и состояния

### Главная и поиск

- В шапке авторизованного пользователя — его реальное имя, а не слово «Профиль».
  Имя ведёт в собственный профиль. Для гостя — «Войти» и «Регистрация».
- Поиск выбирает навыки из справочника с подсказками, а не разбирает произвольную
  строку как единственный источник истины. Декоративные skill badges не нужны.
- До выбора навыков и после очистки показываются последние команды с открытым набором.
  Пустой поиск не является ошибкой. Результаты не называть подходящими до фильтрации.
- «Использовать навыки из профиля» доступно вошедшему пользователю с навыками.
  Если навыков нет, предложить заполнить профиль.
- Нет совпадений: «Команд с такими навыками пока нет»; предложить убрать часть
  навыков, сбросить поиск или создать команду.
- Нет открытых команд: «Пока нет команд с открытым набором» и действие создания команды.
- При загрузке не оставлять старый результат как актуальный; сообщать об ожидании.
  Ошибку загрузки показывать с действием повторной попытки, не скрывать.
- Результаты — простые строки: название, описание, недостающие навыки, состав
  числом и ссылка на отдельную страницу команды.

### Команда

Отдельная страница: описание, технологии, участники текстом, недостающие навыки
и форма заявки. Не разворачивать всю команду на главной. Учитывать гостя,
уже отправленную заявку, участника команды, капитана и закрытый набор;
не предлагать повторную заявку или вступление в закрытую команду.
Действия капитана не показывать обычному посетителю.

### Профиль

Сведения, навыки и ссылки, свои команды, заявки, приглашения и настройки.
Заявки и настройки доступны только владельцу, не входят в публичный профиль.
Статусы из `ApplicationStatus`: `Pending` — «На рассмотрении», `Accepted` —
«Принята», `Rejected` — «Отклонена», `Withdrawn` — «Отозвана», `Cancelled` —
«Отменена». Статусы подписаны словами, без декоративных бейджей и зависимости от цвета.
Отозвать можно ожидающую заявку. Для отсутствующих заявок и команд — короткое
пояснение и ссылка к поиску. Приглашения показывать отдельно от исходящих заявок.

### Администрирование

Доступ только администратору с обязательной серверной проверкой роли.
Макет показывает вкладку пользователей: поиск по имени/email, фильтр по роли,
таблица и изменение роли. Вкладки команд и навыков — части будущей вёрстки,
их содержимое ещё не прорисовано. Не добавлять аналитические карточки,
блокировки, массовое удаление или другие неоговорённые функции.

### Вход и регистрация

Переиспользовать существующие формы `Views/SignIn.html`, `Views/SignUp.html`
и модули из `static/js/pages/`, сохранив имена полей, `data-*`, ID ошибок, проверки,
autocomplete, переключатель пароля и поведение отправки. Вход: email и пароль.
Регистрация: имя и фамилия, email, пароль от 15 до 128 символов без пробельных
символов. Вход сохраняет совместимость с ранее созданными паролями; пароль
не обрезать и не очищать автоматически. Не добавлять OAuth, подтверждение пароля
или восстановление без отдельной задачи.
Предусмотреть ошибки полей и формы, отправку и уведомление об успешной регистрации.

## Порядок реализации и проверки

Сначала общие стили и шапка, затем существующие формы, главная, команда,
профиль и администрирование в рамках запрошенных шагов. Переиспользовать
Bootstrap и обычный JavaScript. Не менять серверные контракты ради скриншота.
Маршруты новых страниц и сохранение настроек определить при реализации,
не считать их уже существующими.

На текущем шаге перевёрстаны только существующие главная, вход и регистрация.
На главной сохранены реальные действия с аккаунтом; поиск, каталог команд
и ссылки на ещё не существующие страницы не добавлены. Они остаются в макетах
до реализации соответствующих сценариев.

Для проверки: настоящий шрифт и fallback, клавиатура и видимый focus,
контраст всех акцентов, заполненные/пустые/ошибочные состояния, масштаб текста,
мобильная ширина. Иконкам без текста нужны доступные имена; декоративным —
`aria-hidden`. Проверки создавать во временной папке вне проекта.

## JavaScript

Нативные ES-модули, подключаемые через `type="module"`, без сборщика:

- `static/js/api/auth-api.js` — запросы к существующим endpoints авторизации.
- `static/js/pages/auth/index.js`, `pages/home/index.js` — события и сценарии страниц.
- `static/js/pages/auth/components/`, `pages/home/components/` — обновление динамических частей формы и шапки.
- `static/js/api/client.js` — общий экземпляр HTTP-клиента с `baseURL: "/api"`, методами `get`/`post` и ответом `{ data, status, headers }`.
- `static/js/shared/http.js` — JSON, cookie, HTTP-ошибки и ошибки соединения; без DOM.
- `static/js/shared/error-messages.js` — общие сообщения об ошибках на английском.
- `static/js/shared/ui.js` — общие функции показа и очистки сообщений.

Структура адаптирована из [bulky-web](https://github.com/Cortexxxx/bulky-web/tree/main/Web/www/public/js).
Сохранять разделение при добавлении следующих страниц; не добавлять пустые модули заранее.
